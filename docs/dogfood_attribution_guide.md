# Dogfood Attribution and Evidence Integrity Guide

## Purpose

This guide establishes the mandatory attribution taxonomy and contribution verification standards for all dogfood experiments across the Howl ecosystem (`howlcreate`, `howldream`, `howl-provider-core`, `howlplane`, `howlframe`).

The goal is to maintain epistemic truthfulness, prevent post-hoc narrative inflation, and strictly delineate between pre-existing engineering knowledge and concepts genuinely originated by autonomous Howl pipelines.

---

## 1. Core Taxonomy: `PREEXISTING` vs `HOWL_ORIGINATED`

Every concept, mechanism, claim, architectural pattern, and test assertion documented in dogfood experiments must be classified into one of the following two canonical origins:

### `PREEXISTING`
- **Definition**: Any architectural pattern, domain knowledge, library capability, protocol specification, test fixture, or engineering convention that existed prior to or independent of the specific Howl execution run.
- **Examples**:
  - Standard algorithmic techniques (e.g., Lamport timestamps, Raft consensus, eBPF socket tracing).
  - External library behaviors and Linux kernel semantics.
  - Operator-supplied problem constraints and objectives.
  - Test harness design and human-authored evaluation scripts.
- **Rule**: Must never be credited as a Howl invention. Stated as context, prerequisite, or baseline constraint.

### `HOWL_ORIGINATED`
- **Definition**: A distinct, non-trivial concept, mechanism inversion, constraint synthesis, or adversarial challenge produced directly within a Howl run and recorded in the lineage DAG.
- **Examples**:
  - Novel problem reframings generated by `ReframingOperator` or `AssumptionOperator`.
  - Emergent hybrid architectures synthesized across divergent branches.
  - Specific adversarial test cases or counter-examples generated in `nightmare` mode.
  - Hard-constraint-satisfying mechanisms selected during convergence.
- **Rule**: Must be backed by a verifiable run ID, node ID in the Lineage DAG, prompt hash, and output hash.

---

## 3. Strict Integrity Rules

1. **No Retrospective Reclassification**: Concepts cannot be upgraded from `PREEXISTING` to `HOWL_ORIGINATED` without DAG provenance.
2. **Epistemic Modality Preservation**: Hypotheses and speculations generated by models must remain labeled as `IMAGINED_POSSIBILITY` or `UNVERIFIED` until corroborated by deterministic evidence.
3. **Audit Trail Completeness**: When a candidate is transferred from HowlCreate to HowlDream, the source run ID, candidate ID, parent request ID, and execution metadata must be preserved without recursion bloat.
4. **Adversarial Honesty**: If an exploration run fails or produces empty/invalid outputs, record `INVALID_PROVIDER_OUTPUT` or `NO_VIABLE_CANDIDATES`. Never substitute a synthetic "clean" result for an actual run.
