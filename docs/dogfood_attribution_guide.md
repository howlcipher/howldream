# Dogfood Attribution and Evidence Integrity Guide

## Purpose

This guide establishes the mandatory attribution taxonomy and contribution verification standards for all dogfood experiments across the Howl ecosystem (`howlcreate`, `howldream`, `howl-provider-core`, `howlplane`, `howlframe`).

The goal is to maintain epistemic truthfulness, prevent post-hoc narrative inflation, and strictly delineate between pre-existing engineering knowledge and concepts genuinely originated, refined, challenged, or validated by autonomous Howl pipelines.

---

## 1. Canonical Attribution Taxonomy

Every concept, mechanism, claim, architectural pattern, test assertion, and design change documented in dogfood experiments must be classified into one of the following canonical categories:

### `PREEXISTING`
- **Definition**: Any architectural pattern, domain knowledge, library capability, protocol specification, test fixture, or engineering convention that existed prior to or independent of the specific Howl execution run, including anything present in initial requirements, pre-Howl designs, or baseline architectures.
- **Rule**: Must never be credited as a Howl invention. Stated as context, prerequisite, or baseline constraint.

### `HOWL_ORIGINATED`
- **Definition**: A distinct, non-trivial concept, mechanism synthesis, or structural design produced directly within a Howl run and recorded in the lineage DAG that did not exist in prior requirements or baselines, and was subsequently adopted into the implementation.
- **Rule**: Must be backed by a verifiable run ID, node ID in the Lineage DAG, prompt hash, and output hash.

### `HOWL_REFINED`
- **Definition**: An idea or mechanism that existed previously, but whose specific parameters, safety boundaries, algorithms, or failure handling were substantially improved or clarified by Howl output.
- **Rule**: Must identify both the preexisting baseline and the specific Howl modification.

### `HOWL_CHALLENGED`
- **Definition**: A baseline requirement, architectural assumption, or candidate design that was refuted, invalidated, or abandoned because Howl produced counter-evidence, invariant violation proofs, or adversarial nightmare scenarios demonstrating its failure.
- **Rule**: Must link to the specific evidence artifact or verification failure demonstrating the invalidation.

### `HOWL_VALIDATED`
- **Definition**: A preexisting or proposed mechanism that was empirically proven sound or verified against formal invariants through Howl's deterministic evidence checks.
- **Rule**: Attributed only when accompanied by passing deterministic check records, not model speculation.

### `HOWL_INSPIRED_TEST`
- **Definition**: A test case, benchmark scenario, or verification harness specifically authored or added to cover an edge case, fault mode, or boundary condition surfaced during Howl divergence or adversarial analysis.
- **Rule**: Must cite the specific Howl hypothesis or failure mode that prompted the test.

### `HOWL_NO_EFFECT`
- **Definition**: Suggestions, concepts, or critiques generated by Howl that were redundant, irrelevant, ignored, or rejected by human operators or convergence filtering.
- **Rule**: Must be transparently recorded to prevent survivor bias in reporting.

## 2. Strict Chronology Precedence Rule (Anti-CascadeSentry Rule)

To prevent retrospective over-crediting:

> **A feature, constraint, or mechanism listed in the initial requirements, pre-Howl design, or baseline architecture MUST NOT later become `HOWL_ORIGINATED` simply because Howl independently suggested the same thing.**

### Illustrative Attribution Scenarios

| Scenario | Initial Requirement / Context | Howl Output | Eventual Implementation | Canonical Attribution |
|:---|:---|:---|:---|:---|
| **A: Independent Confirmation** | *"Use adaptive concurrency limiting."* | Proposes adaptive concurrency limiting. | Implemented as required. | `PREEXISTING` (independently confirmed) |
| **B: Novel Mechanism** | *No retry strategy specified in requirements.* | Proposes retry budget with bounded decorrelated jitter. | Retry budget implemented directly from output. | `HOWL_ORIGINATED` |
| **C: Invariant Refutation** | *Initial design uses Design A.* | Dream evidence demonstrates Design A violates external invariant. | Design A removed from system. | `HOWL_CHALLENGED` |
| **D: Safety Parameter Refinement** | *Standard token bucket specified.* | Dream identifies burst starvation under GC pause; tunes burst multiplier. | Burst multiplier tuned per recommendation. | `HOWL_REFINED` |
| **E: Adversarial Test Inspiration** | *Basic lease renewal tested.* | Dream generates nightmare clock skew desync scenario. | Skew regression test added to test suite. | `HOWL_INSPIRED_TEST` |
| **F: Redundant / Unused Idea** | *Queue system proposed.* | Proposes Paxos-backed queue. | Retained standard channel; idea ignored. | `HOWL_NO_EFFECT` |

All future dogfood report artifacts (e.g., `dogfood_run_*.md`) must include an explicit Attribution Matrix formatted as follows:

| Mechanism / Concept | Origin Category | Source Artifact / Node ID | Verification Status | Attributed Impact |
|:---|:---|:---|:---|:---|
| *Monotonic Epoch Barrier* | `HOWL_ORIGINATED` | `run-20261001-e2e/c1` | `LOCALLY_VERIFIED` | Novel lease renewal mechanism satisfying zero wall-clock constraint |

## 4. Strict Integrity Invariants

1. **No Retrospective Reclassification**: Concepts cannot be upgraded to `HOWL_ORIGINATED` without DAG provenance and proof of absence from baseline.
2. **Epistemic Modality Preservation**: Hypotheses and speculations generated by models must remain labeled as `IMAGINED_POSSIBILITY` or `UNVERIFIED` until corroborated by deterministic evidence.
3. **Audit Trail Completeness**: When a candidate is transferred from HowlCreate to HowlDream, the source run ID, candidate ID, parent request ID, and execution metadata must be preserved without recursion bloat.
4. **Adversarial Honesty**: If an exploration run fails or produces empty/invalid outputs, record `INVALID_PROVIDER_OUTPUT` or `NO_VIABLE_CANDIDATES`. Never substitute a synthetic "clean" result for an actual run.
